COME FUNZIONA IL CHATBOT (flusso completo)
─────────────────────────────────────────────

  Avvio server (una sola volta):
    1. Python importa chat_service.py
    2. _load_kb() legge i 4 file .md in ordine fisso:
       kb_azienda.md → kb_prodotto.md → kb_faq.md → kb_glossario.md
    3. I 4 file vengono uniti in KB_CONTENT (separati da "---")
    4. SYSTEM_PROMPT = regole + 8 esempi + "KNOWLEDGE BASE:" + KB_CONTENT
    5. _kb_loaded_at = orario di caricamento (per la dashboard)

  Per ogni messaggio cliente:
    1. POST /api/chat  →  dashboard.py  →  chat_service.chat()
    2. Verifica rate limit (max 30 msg/ora per IP)
    3. Recupera o crea sessione (dict in RAM, TTL 24h)
    4. Aggiunge messaggio alla history (max 10 messaggi = 5 turni)
    5. Chiama API Anthropic:
         model: claude-haiku-4-5-20251001
         max_tokens: 800
         system: [SYSTEM_PROMPT, cache_control: ephemeral]
         messages: [ultimi 10 msg della sessione]
    6. Risposta restituita come {"ok": true, "reply": "..."}

  Cosa vede Claude in ogni chiamata:
    [SYSTEM — cacheable]
      • 8 regole di comportamento
      • 8 dialoghi modello (IT/ES/EN/FR/DE)
      • kb_azienda.md  — chi siamo/non siamo, contatti (5 lingue)
      • kb_prodotto.md — piani, filtri, prezzi, score (5 lingue)
      • kb_faq.md      — FAQ accesso/report/pagamenti (5 lingue)
      • kb_glossario.md — EV/FCF, TER, Sharpe, UCITS… (5 lingue)
    [MESSAGES]
      • Ultimi 10 messaggi della sessione corrente

  Cosa NON sa Claude:
    • Chi è il cliente loggato
    • Il contenuto dei report Excel
    • Dati di mercato in tempo reale
    • Qualsiasi cosa non sia nella KB

PROMPT CACHING:
  Il system prompt (~55.500 chars) viene inviato ad ogni chiamata
  ma è cacheable lato Anthropic (cache_control: ephemeral, TTL 5 min).
  Con traffico sostenuto il risparmio è ~10x sui token di input.

COME AGGIORNARE LA KB SENZA RIAVVIARE:
  1. Modifica/aggiungi file .md in KNOWLEDGE_BASE/
  2. Vai nella dashboard admin → tab Home
  3. Clicca "↺ Ricarica KB"
  4. Il chatbot usa la nuova KB da quel momento in poi

PARAMETRI SESSIONE:
  RATE_LIMIT  = 30 messaggi / ora / IP
  MAX_HISTORY = 10 messaggi per sessione (5 turni)
  MAX_MSG_LEN = 600 caratteri per messaggio
  SESSION_TTL = 24 ore (pulizia automatica sessioni inattive)
  Pulizia:    thread cleanup ogni 1h (avviato da dashboard.py al boot)

FILE KB (KNOWLEDGE_BASE/):
  kb_azienda.md   — identità, contatti, disclaimer
  kb_prodotto.md  — tutti i piani con filtri e prezzi
  kb_faq.md       — domande frequenti
